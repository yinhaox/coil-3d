# Design: Core rules

_一局 Coil 3D 的底层规则：网格、蛇身、转向、食物、碰撞、计分与速度曲线。负责人：game-designer。_

Serves pillar: **一眼读懂的三维空间**、**越吃越快的心跳**。

## Goals

- 让一条蛇的移动、变长和死亡在四个方向键下完全可预测，失败能归因到某一次转向。
- 把规则收敛为一个纯逻辑状态机，headless 测试可以直接调用 `step()` 断言边界情况。
- 为三种模式共用同一套规则，模式差异只来自场地数据（见 [game-modes.md](game-modes.md)）。

## Player experience

玩家看到一条青色蛇从场地中央出发，每吃一颗橙色食物身体长一格、速度略快；转向是瞬时的，蛇头立即朝新方向滑出去。撞到墙、障碍或自己的身体时，画面停顿一下、蛇身变暗，结算页说明是哪一种碰撞。玩家在第三局开始学会预判两步，而不是只看眼前一格。

## Rules

1. **场地**：蛇在一个 XZ 平面网格上移动，格子坐标 `Vector2i(x, z)`，`x` 为 0..columns-1，`z` 为 0..rows-1。四面边界始终是实心墙，没有穿墙。
2. **蛇身**：蛇是一条格子队列，`head` 在队首；初始长度 4 格，从场地中心沿起始方向反方向铺开；蛇头与身体永不同格。
3. **方向**：方向枚举为 east `(+1, 0)`、west `(-1, 0)`、north `(0, -1)`、south `(0, +1)`。输入进入长度 2 的待转队列；与队列中最后一个方向相同或相反的输入被丢弃，因此两次快速反向不会让蛇撞死自己。默认绑定提案：`W`/`↑` = north、`S`/`↓` = south、`A`/`←` = west、`D`/`→` = east，按世界轴映射，待试玩确认。
4. **步进**：逻辑按固定步长推进，`step_duration_seconds = 1.0 / speed_cells_per_second`。帧循环用累加器驱动，每帧最多执行 4 步，避免卡顿后死亡螺旋；表现层在上一格与当前格之间按 `accumulator / step_duration` 插值。
5. **移动**：每个逻辑步先计算新蛇头；新蛇头不在食物格时先移除队尾，在食物格时不移动队尾、长度 +1、得分 +10，随后补生食物。
6. **食物**：食物只生成在既不是蛇身、也不是障碍的格子上，均匀随机；场上食物数维持为场地的 `food_max`；被吃后立即补一颗；蛇身与障碍占满所有格子时本局以“清场”结束，空格不足时只补可用数量。
7. **碰撞**：新蛇头越界、进入障碍格、或进入移除队尾后仍被蛇身占据的格子，本局结束；本步吃食物（不移除队尾）时按完整身体判定。进入本步即将空出的队尾格是合法的，因为尾巴先离开。
8. **计分**：每颗食物 +10 分；得分只用于本局分数与每模式最高分，不改变长度以外的规则。
9. **速度**：`speed = min(initial_speed + 0.2 × food_eaten, max_speed)`，吃到食物立刻生效，下一步开始使用新步长；速度上限后不再提升。
10. **状态**：`idle → countdown → playing ⇄ paused → over`。开局与暂停恢复各有 1.0 秒倒计时，倒计时中忽略转向输入；暂停冻结累加器与倒计时；结束状态只记录本局结果，重开创建全新状态机。
11. **结束原因**：`wall`、`obstacle`、`self`、`time_up`、`cleared` 五种，结算页与日志使用同一枚举；撞墙/障碍/自己优先于同一逻辑步内到达的时间上限。
12. **最高分**：本局结束时，若分数严格大于该模式最高分则写入存档；平局不刷新。

## Numbers and tuning

| Value | Default | Range | Unit | Tuned in |
|---|---|---|---|---|
| `columns` / `rows` | 16 / 16 | 4–16 | cells | 场地 JSON |
| 初始长度 | 4 | 3–8 | segments | `core-rules` 常量，需与场地起始空间匹配 |
| 逻辑帧上限 | 60 | 30–120 | steps/s | 帧循环累加器 |
| 单步时长 | 1 / speed | 0.05–0.30 | seconds | 由速度推导 |
| Classic 初始速度 | 6.0 | 4.0–10.0 | cells/s | 场地 JSON |
| 每次食物加速 | 0.20 | 0.05–0.50 | cells/s per food | `core-rules` 常量 |
| 速度上限 | 14.0 | 8.0–20.0 | cells/s | 场地 JSON |
| 每颗食物得分 | 10 | 1–100 | points | `core-rules` 常量 |
| 待转队列长度 | 2 | 1–2 | inputs | `core-rules` 常量 |
| 开局/恢复倒计时 | 1.0 | 0.0–3.0 | seconds | UX/规则常量 |
| 每帧最大步数 | 4 | 1–8 | steps | 帧循环累加器 |
| 食物数量上限 | 1 / 2 / 3 | 1–8 | items | 场地 JSON（Classic/Maze/Time Attack） |

表中未由 issue 指定的值均为提案，见 Open questions。

## Edge cases

- 蛇头进入本步队尾格：合法；若本步吃食物（不移动队尾）则改为碰撞。
- 一帧内两次转向：只取队列第一个；第二个若与第一个相反则丢弃，不改变本步方向。
- 暂停发生在两步之间：当前步完整结束后冻结；恢复先走 1.0 秒倒计时。
- 时间上限在一步中途到达：先完成该步并判定碰撞；未碰撞则 `time_up` 结束。
- 场地被蛇填满：`cleared` 结束；若同时吃到最后一颗食物，先结算成长与得分，再结束。
- `food_max` 大于可用空格：只生成空格数量的食物，不等待、不阻塞。
- 速度达到上限：继续按上限步进，不再变化。
- 窗口失焦：桌面端 0.5 秒后自动暂停（见 [ux-and-persistence.md](ux-and-persistence.md)）。
- 重开：分数清零，最高分从存档读取，随机种子重新生成。

## Open questions

- 调参基线（初始速度 6.0、每食物 +0.2、上限 14、每食物 10 分）需要至少 3 次试玩确认；负责人：game-designer。
- 键盘方向按世界轴（“上”= 远离相机）还是按屏幕轴映射，需在原型上试玩后定稿；负责人：game-designer。
- 开局 1.0 秒倒计时是否足够，还是会拖慢连续重开；负责人：game-designer。
